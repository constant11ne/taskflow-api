# TaskFlow API

Небольшой сервис для студентов и личного планирования: создаёт задачи,
помогает искать их, менять статус, выбирать приоритет и видеть прогресс.
Проект реализован на FastAPI. Для обычной работы есть страница с задачами
по адресу `/`; для изучения и проверки отдельных запросов — Swagger UI в `/docs`.

**Ограничение:** данные находятся в памяти процесса и очищаются при перезапуске.
Запускайте один процесс Uvicorn без `--workers`. Это учебный локальный сервис
без авторизации; база данных и внешний сервер для задания не нужны.

## Установка

Нужны Python 3.12 и Git. В терминале перейдите в корень проекта.
После клонирования репозитория также выполняйте команды из его корня.

macOS / Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
```

Если команда `python3.12` отсутствует, используйте `python3`, предварительно
убедившись командой `python3 --version`, что установлена версия 3.12.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

Для работы приложения без тестов достаточно `python -m pip install -r requirements.txt`.
Файл `.env` необязателен: при его отсутствии используются значения по умолчанию.
Настоящий `.env` и виртуальное окружение исключены из Git.

## Запуск

Обычный запуск:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Откройте [страницу TaskFlow](http://127.0.0.1:8000/): добавьте задачу,
смените её статус, попробуйте поиск и фильтры. Счётчики и прогресс обновляются
после каждого действия. Для проверки отдельных API-запросов откройте
[интерактивную документацию](http://127.0.0.1:8000/docs), выберите маршрут,
нажмите **Try it out**, заполните параметры и нажмите **Execute**.
Остановка сервера: `Ctrl+C` в терминале или Stop в PyCharm.

При разработке можно добавить `--reload`:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000 --reload
```

В режиме `--reload` изменение кода перезапускает процесс и очищает задачи.

### PyCharm

1. Откройте папку `taskflow-api` через **File → Open**.
2. Выберите интерпретатор проекта `.venv/bin/python` (Windows: `.venv\Scripts\python.exe`).
3. Выберите готовую конфигурацию **TaskFlow API** и нажмите Run. Затем откройте
   `http://127.0.0.1:8000/` в браузере.
4. Для тестов выполните `python -m pytest -v` во вкладке Terminal
   с активированным окружением проекта.

Если конфигурация не появилась: **Run → Edit Configurations → + → Python**,
запуск **Module name** = `uvicorn`, параметры
`app_final:app --host 127.0.0.1 --port 8000`, рабочая папка = корень проекта.

## Маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/` | Страница для работы с задачами |
| GET | `/health` | Проверка работоспособности |
| GET | `/version` | Версия и название из настроек |
| GET | `/tasks` | Список, поиск, фильтры и постраничная выдача |
| POST | `/tasks` | Создание задачи |
| GET | `/tasks/{task_id}` | Задача по идентификатору |
| PATCH | `/tasks/{task_id}` | Изменение статуса |
| DELETE | `/tasks/{task_id}` | Удаление задачи |
| GET | `/stats` | Количество задач по статусам и процент выполнения |

Статусы: `todo`, `in_progress`, `done`. Приоритеты: `low`, `normal`, `high`.
Идентификатор — положительное целое число. Название — 1–120 символов,
описание — до 1000 символов. Пустые названия и неизвестные поля отклоняются.

### Пример работы (macOS / Linux)

```bash
curl -i -X POST http://127.0.0.1:8000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Подготовить итоговый проект","priority":"high"}'

curl http://127.0.0.1:8000/tasks/1

curl -X PATCH http://127.0.0.1:8000/tasks/1 \
  -H 'Content-Type: application/json' -d '{"status":"done"}'

curl 'http://127.0.0.1:8000/tasks?status=done&priority=high&limit=10&offset=0'
curl -G http://127.0.0.1:8000/tasks --data-urlencode 'q=проект'
curl http://127.0.0.1:8000/stats
curl -i -X DELETE http://127.0.0.1:8000/tasks/1
```

В Windows используйте `/docs` или `curl.exe`. Идентификатор `1` в примере
предполагает первую задачу после запуска; фактический ID есть в ответе создания.
Поиск `q` не учитывает регистр. Фильтры применяются совместно перед пагинацией.
`limit` — от 1 до 100 (по умолчанию 50); `offset` — от 0.
Статистика учитывает все задачи, независимо от пагинации.

## Переменные окружения

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `APP_NAME` | `TaskFlow API` | Название сервиса и заголовок `/docs` |
| `APP_VERSION` | `1.0.0` | Версия для `/version` и OpenAPI |
| `MAX_TASKS` | `1000` | Максимальное число задач в памяти, целое число больше 0 |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |

Настройки читаются при создании приложения. `.env` загружается автоматически
библиотекой `python-dotenv`; уже заданные системные переменные имеют приоритет.
После изменения настроек перезапустите сервис. Некорректные настройки
вызывают понятную ошибку при запуске.

## Автоматические тесты

```bash
python -m pytest -v
python -m pip check
```

Проверяются `/health`, настройки `/version`, жизненный цикл задачи, ID,
фильтры и поиск, пагинация, статистика, валидация, ошибки 404/409/422,
лимит задач, изоляция хранилищ, наличие документации и записи в логах.
Тесты создают отдельные приложения и не меняют данные работающего сервера.

## CI и artifact

Workflow `.github/workflows/ci.yml` срабатывает на `push`, `pull_request`
и вручную через `workflow_dispatch`. На Ubuntu с Python 3.12 он устанавливает
фиксированные зависимости, выполняет `pip check` и `python -m pytest -v`.
Только после успешных проверок `git archive` собирает ZIP из файлов коммита,
а `upload-artifact` сохраняет его как `taskflow-api-<SHA>` на 14 дней.
Виртуальное окружение, логи и локальный `.env` в архив не попадают.

После публикации откройте вкладку **Actions**, выберите последний запуск
**Python CI**, убедитесь в зелёном результате и наличии раздела **Artifacts**.
Подготовленный workflow сам по себе ещё не означает успешный запуск в GitHub.

## Диагностика и логи

```bash
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8000/version
```

Ожидается HTTP 200; `/health` возвращает `{"status":"ok"}`.
Логи запуска, остановки, метода/пути запроса, HTTP-кода, времени обработки
и событий с задачами выводятся в терминал или окно Run в PyCharm.
Тексты задач, тела запросов и query-параметры приложение в лог не записывает.
При `LOG_LEVEL=WARNING` информационные записи скрываются; для диагностики используйте `INFO`.

Для записи в файл:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000 > app.log 2>&1
```

| Симптом | Что проверить |
| --- | --- |
| `ModuleNotFoundError` | Выбран ли Python из `.venv`; повторить установку зависимостей |
| `Address already in use` | Остановить предыдущий запуск или задать `--port 8001` |
| Не открывается `/docs` | Сервер запущен, адрес и порт совпадают с командой |
| HTTP 404 | Задача существует; после рестарта список очищается |
| HTTP 422 | Проверить ID, JSON, статус, приоритет и ограничения в `/docs` |
| HTTP 409 | Достигнут `MAX_TASKS`: удалить задачу или изменить лимит и перезапустить |
| Ошибка `MAX_TASKS` / `LOG_LEVEL` при старте | Исправить `.env` или системные переменные |
| Разные списки в разных запросах | Использовать один процесс без `--workers` |

## Соответствие заданию

Содержательные доработки: собственная тема и логика задач, приоритеты и статусы,
поиск с фильтрацией, пагинация, статистика, валидация входных данных,
лимит через окружение, собственные тесты и диагностические логи.
Проект создан с нуля; код учебного примера не копировался.

В Git сохранены отдельные осмысленные коммиты по этапам работы. Проект
опубликован в [публичном репозитории](https://github.com/constant11ne/taskflow-api).
[GitHub Actions](https://github.com/constant11ne/taskflow-api/actions) проверяет
тесты после каждого push и прикладывает ZIP-архив приложения к успешному запуску.
Настоящий `.env` в Git не добавляйте.

Преподавателю нужны ссылка на публичный репозиторий, ссылка на зелёный запуск
Actions и описание: «TaskFlow API помогает создавать задачи, управлять их
статусом и приоритетом, искать задачи и отслеживать прогресс выполнения».
